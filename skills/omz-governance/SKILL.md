# OMZ 机制流程参考

ZERONE 模式的完整流程细节。红线与角色常驻 persona，本技能承载可查细节，进入对应阶段时加载。

## 1. SDD 工作流

### fe-dev 前端开发工作流

1. **step1 [询问]** — 通过细节询问直到需求对齐；禁止直接改动代码；技能 `/grill-with-docs`；用户确认：是
2. **step2 [需求整理]** — 将讨论结果整理为 `.PRD/<version>.md` PRD（SemVer 升位）；禁止直接改代码；技能 `/to-prd`；用户确认：是
3. **step3 [切片]** — 将 PRD 垂直切片为 issue 并创建 `.ISSUE/<version>-N-slug.md`；禁止直接改代码；技能 `/to-issues`；用户确认：是
4. **step4 [开发]** — 按 PRD TODOQ 逐项编码，遵循编码规则；禁止用 npm 脚本尝试验证；技能 `/to-coding`；用户确认：自动
5. **step5 [测试]** — issue 与 PRD TODO 测试回收；未验收通过的 issue 禁止打勾；技能 `/to-test`
6. **step6 [审查]** — 全面审查并反馈，遵循 review 规范；技能 `/to-review`
7. **step7 [提交代码]** — 基于本次改动生成 commit 信息并提交，提交后引导/询问是否提交 PR；技能 `/to-commit`

### fe-locate 前端问题定位工作流

- **step1 [术语与问题澄清]** — 读取已有信息；对不确定业务词汇/页面/模块逐项澄清，每次只问一个关键问题并给出推荐理解；不改代码、不创建 PRD/issue
- **step2 [只读定位]** — 按"文档/知识 → 路由/菜单 → 页面 → 组件 → 状态/接口 → 样式"检索；按问题类型调整优先级；定位到文件路径与符号名；不运行改变工作区状态的命令
- **step3 [定位报告]** — 输出定位报告（确认后需求、问题类型、代码定位、证据、影响范围、可交给 /to-coding 的任务描述）；说明流程边界

技能 `/to-locate`。

### fe-explain 项目解释工作流

- **step1 [解释对象澄清]** — 识别代码对象/业务对象；输入模糊时一次一问并给出推荐理解
- **step2 [只读信息收集]** — 按优先级读取项目文档；只读检索证据；核心结论绑定证据来源；文档与代码冲突时以代码为准并标记文档疑似过期
- **step3 [解释报告]** — 输出学习理解说明书（一句话结论、证据来源、关键入口、Mermaid 关系图、事实/推断/待确认、容易误解点、建议阅读顺序、进化观察）；说明流程边界

技能 `/to-explain`。

## 2. Review 审查规范

### 输出规范（每项检查至少包含）

- 状态：`通过` / `未通过` / `待确认`
- 证据：文件路径和判断依据
- 问题：未发现时写 `未发现`
- 建议：无建议时写 `无`
- 结论：说明该项是否完成到位

### 最终结果规则

- 任一检查项为 `未通过` → 最终结果为 `未通过`
- 无 `未通过` 但存在 `待确认` → 最终结果为 `待确认`
- 全部 `通过` → 最终结果为 `通过`

### 本次 Review 清单格式

只有标题行 `本次 review 清单：` 之后紧邻的连续 `- ` 列表会被视为正式检查项；普通描述只作为上下文。

### 复检说明

优先检查上次报告的 `未通过` 和 `待确认` 项，逐项说明：`已关闭` / `仍未通过` / `仍待确认`；无上次报告则执行完整 Review。

## 3. 进化机制

### 权限边界

- **可自主**：识别进化机会、整理进化申请、写入/更新/废弃记忆（`docs/agent/memory.md`）、记忆落盘后写简短进化日志
- **需用户确认**：添加或更新 `docs/knowledge/` 知识库、创建或更新 skill、修改长期规则/工作流/AGENTS.md 等项目级约束
- **禁止**：未确认前创建/修改知识库与 skill 文件、把未验证猜测写成项目事实、把一次性任务细节写成长期规则、删除或覆盖历史规则来扩大权限、记录密钥/账号/token/隐私等敏感信息

### 申请格式

```md
[进化申请-知识库]
原因：
来源：
拟写入：
目标文件：
内容摘要：
风险：
需要用户确认：是
```

```md
[进化申请-技能]
触发原因：
证据：
拟修改对象：
拟修改内容：
影响范围：
风险：
需要用户确认：是
```

未获确认前只能在回复中提供申请与草案，不得创建或修改对应文件。

### 记忆记录格式（caveman 风格：短、准、长期有效）

```md
- 日期：YYYY-MM-DD
  来源文件：文件路径或 user-chat:YYYY-MM-DD
  用户原话摘要：用户内容精简版
  分类：中文分类
  内容：caveman 风格记忆
  状态：生效 / 待确认 / 已废弃 / 已替换
  替代：无或被替代记忆摘要
```

### 记忆冲突处理

用户当前内容与旧记忆冲突时不自动覆盖：列出旧记忆、新说法、冲突点，向用户确认哪个正确；确认前不更新旧记忆、不写冲突内容、不记日志。

### 进化触发节点

1. 深度讨论后获得长期有效新信息
2. 用户提出重点背景、协作原则、长期偏好
3. 用户反驳或纠正已形成的记忆
4. 内容中明确出现 `[进化-xxx]` 标记
5. 现有能力无法稳定完成某类重复任务
6. 用户多次纠正同一 skill 的执行产物

## 4. 用户确认机制

- 技能/规则中出现 [用户确认] 环节 → 暂停执行，提供上下文信息反馈用户，确保用户理解当前行为
- 用户对所做内容存在质疑 → 主动提供执行历史链路，询问是否存在理解误差
- 用户不理解 → 像老师教学生一样讲解思路、流程、步骤，直到理解
- 收到"自动执行"授权 → 自动推进后续流程、暂时跳过 [用户确认]，step 完成后告知所有细节并消除授权
- 授权可带明确目标（如"自动执行到 TODO 第 5 条"）——到达目标即消除，回到确认机制
- 用户发出"停止自动执行"等意图命令 → 移除授权，回到确认机制

## 5. 编码规则（rules/coding.mdc）

### Ai 标记

生成的代码必须在顶部添加 `@by oh-my-zerone` 的文档注释或普通注释，说明代码来自 AI 与时间。

```js
/**
 * @by oh-my-zerone
 */
```

### Import 分组（Vue `<script>` / `<script setup>`）

按顺序分块，块首使用小写英文注释；没有引用的块直接省略：

1. `// components`：UI 组件库、公共组件、同步引入的 `.vue` 组件
2. `// hooks`：vue Composition API、业务 hooks、`@zerone/toolbox`、`model.js` 解析函数
3. `// const`：常量、枚举、静态配置
4. `// services`：`@/api/*`、当前功能目录 `service.js`、其他请求模块

新增分组放在 `// services` 之后，并保持同目录风格一致。
